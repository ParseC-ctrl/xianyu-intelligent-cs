# 材质知识库客服定制版

本地开发分支保留上游 GPL-3.0-only 许可与来源说明。`upstream` 指向原项目，定制功能通过本地 Git 分支管理。不要用原项目网页更新覆盖定制代码；纯客服部署已关闭上游更新入口。

## macOS 与 Windows

完整后端需要 Linux 内核。在 macOS 使用 Colima 或 Docker Desktop；在 Windows 使用 WSL2 内原生 Docker Engine + Compose 插件（具体步骤见根目录 `WINDOWS-DEPLOYMENT.md`），并将项目放在 WSL2 的 Linux 文件系统中。两个宿主机运行相同的 Dockerfile、Python 依赖与配置，服务端不使用宿主机绝对路径。Apple Silicon 和常见 Windows x86_64 需要分别构建对应架构镜像；不能直接把 ARM64 镜像当作 x86_64 镜像使用。

首次启动运行 `bash scripts/customer.sh start`，工作台地址为 `http://127.0.0.1:4173/xianyu-intelligent-cs/`。先创建本地管理员。`config/customer.env` 中的加密主密钥与管理员凭据须保密，不进入 Git。停止运行 `bash scripts/customer.sh stop`；状态与日志分别用 `status`、`logs`。

数据位于 Compose 的 `customer-data` 命名卷。停止、重建容器保留数据；不要运行 `down -v`。迁移电脑时需要备份和迁移数据卷以及 `config/customer.env`，仅复制 Git 仓库不会包含知识库、聊天记录与模型连接。Windows 迁移后仍需重新核验平台登录态，不能假定旧 Cookie 可直接复用。

如果本机网络需要特殊 DNS，可在不进入 Git 的 `.local/compose.local.yml` 中配置。`customer.sh` 自动加载这一可选配置。迁移到 Windows 时不要复制这个机器专用文件；WSL 原生 Engine 使用目标机器自己的网络配置。

## 使用流程

1. 在“客服知识库”导入 `.xlsx`。必需列为货号、鞋面、内里、鞋垫、鞋底；主商品编码、颜色、分类为可选列。导入只更新当前店铺知识库，原文件不会修改。
2. 查询货号，检查冲突和空值。重复且材质一致的记录合并；不同材质的重复货号标记冲突。不会自动猜测有效版本，也不会补填空值。公式仅读取 Excel 已保存的计算结果；修改公式后应先在 Excel 中重新计算并保存。
3. 不连接闲鱼也能填写编码、颜色和问题，点击“仅试答”。不勾选 AI 时为本地规则预览；勾选后使用已配置的模型识别意图并组织自然答复。两者均不向闲鱼发送消息。
4. 在“账号连接”扫码登录；商品快照建立后，系统从标题、描述和已有商家编码字段提取货号。在同步截断描述之前保留编码。接口没有返回编码、多个编码或颜色不确定时，在知识库选择对应商品并保存货号关联。手机上架或修改商品后，按需点击一次“更新商品关联”；页面加载不自动同步。
5. 常见业务问题可在知识库添加 FAQ，填写准确问题与已确认的答复，审核勾选后保存。未审核的草稿不会回答买家；修改问题或答案会取消前端审核勾选，需重新审核保存。FAQ 不替代逐商品材质，当前版本最多 50 条。
6. 在系统设置中测试并保存模型连接。优先可配置 DeepSeek 的 OpenAI 兼容接口；密钥由服务端加密保存，不在浏览器长期缓存。明确启用 AI 并启动客服后，才开始平台收发；本地试答不要求启动客服。

“账号连接”可以修改店铺显示名称。该备注只存入本地工作台数据库，不修改闲鱼昵称，不同步商品，也不产生闲鱼接口请求。

客服专用界面隐藏人工文字、图片发送及快捷短语，原有通用版本的代码与接口保留。专用界面只查看消息并控制会话的 AI 暂停／恢复；人工处理请在闲鱼 App 完成，先暂停对应会话，处理完后明确恢复。

`config/customer-faqs.example.json` 是空结构示例，不包含任何店铺政策或真实知识库。使用者应自行填写和审核 FAQ，再通过知识库保存启用。AI 能理解“能刀吗”“小刀一下”等口语并匹配审核问答，规则预览仅匹配问题或主题的精确别名。通用成色说明不确认单件瑕疵，发货时效不代表实际订单已经发货；没有足够事实时仍保留会话保护。

个人号也使用现有闲鱼 App 扫码入口；本版本没有鱼小铺资格检查。扫码建立登录与商品快照，**不会自动启动客服**。知识模式只接受显式 `rules_ai` 启动；默认规则模式无法绕过知识查询。首次登录出现零商品而实际有商品时，稍后单次点击刷新并检查结果，避免反复登录。

AI 先结合最近对话识别意图，再由程序选择本地资料。四项材质事实由 Excel 精确查得，FAQ 政策来自已审核问答；程序确认资料后，再由模型结合最近 24 条对话组织简短答复。通常每轮增加一次模型调用，不增加闲鱼查询。生成结果检查材质原文、额外数字和部分交易承诺；失败时回退已核实答案，检查不能保证排除所有语义偏差，需结合实际对话持续评估。普通下单方法自动说明商品页流程，实际订单状态仍需核实。

纯“你好／在吗”正常问候，不进入人工接管；“谢谢／收到”会简短回应。天气、娱乐或泄露秘密等无关问题礼貌拒答，之后仍可询问商品。模糊问题先澄清一次；已有商品主款但颜色有多个版本时先确认货号或颜色。明确请求人工、澄清仍无法解决、无法识别对应商品、知识冲突／缺失，或没有完整适用 FAQ 的议价、物流、退款等业务问题转人工。“不要转人工，鞋面是什么材质”不会仅因出现人工二字触发接管。

新的买家消息不会因问候、致谢、内容相同或短期重复而静默；仅同一平台消息事件的重放防止重复发送。加微信／加 v 单独引导留在闲鱼内沟通。资料缺失／冲突、明确人工请求或认证异常仍保留安全保护。本地规则预览只适合核对事实；实际语义识别效果应勾选模型试答。模型识别故障时仅纯问候和致谢可使用确定性兜底，其他问题转人工。

## 人工接管

转人工后发送一次提示并标记待处理，当前会话进入持久接管状态；重启后仍保持，其他会话不受影响。人工在工作台点击“接管”可以主动介入；已排队但未发送的 AI 回复会在发送前再次检查并停止。人工发送后不会自动恢复 AI，必须明确点击“恢复 AI”。通过闲鱼原生客户端介入时，应先在工作台点击接管，或使用既有控制关键词，避免与机器人回显混淆。

Excel、商品对应关系或 FAQ 更新会改变回复版本，发送前会再次核验；旧版本已生成的答复会取消。内部服务超时与预算耗尽也持续转人工。平台已提示风控或认证异常时，不发送额外人工提示。

## 纯客服与账号边界

`compose.customer.yml` 固定启用 `SAAS_KNOWLEDGE_ONLY=1` 与 `SAAS_CUSTOMER_SERVICE_ONLY=1`。前者禁止关键词或通用闲聊绕过知识查询；后者仅展示客服工作台、客服知识库、商品资料、账号连接，以及模型连接和修改密码。上架、订单、卡密、自动发货、运营和网页更新入口不展示，相关后台 API 也返回功能关闭，后台不启动更新探针及运营任务通道。

容器启动器仍读取本地健康、数据库就绪与公开构建版本，以确认实际运行文件；这些检查不访问闲鱼，也不检查上游更新。曾明确启动且未暂停的客服会在容器重启后恢复；进行本地试答或暂不接待时，请使用“暂停客服”，该状态会持续保留。

客服回答使用本地商品快照、人工货号关联、Excel 和 FAQ，不为材质问答抓取平台商品详情。已确认归属的本地商品不额外查询会话头；归属未知时，为避免误答其他卖家的会话，仍可能进行必要且有缓存的归属核验。登录、扫码完成时建立快照、连接维持／令牌续期、收发消息仍需平台通信，因此总请求并非零。手动更新商品关联会产生一次同步任务，应只在商品有变化或快照缺失时使用。风控保护保留，异常后停止请求并等待人工处理。

平台收发仍使用非官方接入，不能保证账号不被风控或封禁。开发和离线验收不需要登录主账号；真实测试使用用户已授权的测试账号，新增账号或扩大测试范围需重新明确范围。

## 验证

`npm run test:knowledge` 包含导入、精确关联、冲突/空值、意图失败、账户隔离、API 权限、人工接管持久性、并发发送和纯客服模式的离线检查。`npm test` 为上游全套回归，完整套件应在 Linux 环境运行。真实模型测试不能代替平台接入验收，也不能证明不会封号。

本轮界面由用户手动验收，开发侧保留语法检查、知识决策／权限／接管测试及本地真实模型试答。建议在自动回复关闭时检查：

- 登录后仅有三个主要页面，设置只提供模型连接与密码修改。
- 从自己提供的 Excel 选择货号，核对查询与商品关联结果。
- 试答“你好”“鞋面是什么材质”“里面呢”“谢谢”“今天天气怎么样”“找人工”，结果符合上述流程；试答不会给买家发消息。
- 新增 FAQ 草稿不能自动回答，审核保存后可回答，修改后需要重新审核。
- 账号连接显示暂停状态，重新扫码不会自动开启客服；需要真人平台测试时再明确启动。
- 工作台能主动接管、人工回复并手动恢复 AI；这一步涉及实际消息，只使用已授权的测试会话。

## 自动货号关联与客服参数

优先识别本地商品快照中的商家编码、已有编码字段，再识别标题和描述中的 Excel 货号。唯一且资料有效时自动关联，不要求逐件手动绑定；多个货号、缺失、冲突不猜测。自动关联随当前资料重新解析，不永久写成可能过期的人工绑定。所需描述未由列表接口返回时，在“商品资料”手动同步会串行补查商品详情；对话中不会额外抓取详情。未来官方商家货号字段可接入同一解析入口。

管理员在“客服知识库 → 回复设置”配置基础延迟（0–60秒）、额外随机延迟（0–60秒）和可选营业时间。实际等待为基础延迟加0到随机延迟；配置只写本地文件，下次消息处理读取生效，不需要扫码或同步商品。营业时间开关启用后，营业外不自动回复；默认保留原有设置。专用知识模式不使用旧触发冷却来丢弃新消息。

## 只读商品资料与详情同步

“商品资料”展示本地商品列表、完整描述、自动货号匹配结果与详情更新时间。打开页面、搜索和查看只查询本地数据，不访问闲鱼。账号页“更新商品关联”和商品页“同步新增／变更”共用同一后台任务；刷新浏览器不会自动重复创建任务。

手动“同步新增／变更”读取商品列表，仅补齐新增、待补或有明确列表变更的商品详情。每批最多20件；增强同步的账号资料、列表分页及详情请求统一串行限频，默认间隔3秒。这个参数只是保守配置，不是平台认可的安全阈值。已就绪且没有明确变化的商品复用缓存；失败商品不会被默认批次反复重试，可以选择“刷新这件商品”。列表更新时间可能不反映正文变更，已修改描述的商品建议单件刷新。

每批保存进度，可暂停、继续或手动处理下一批，不自动无限续批。24小时以内有待补进度时复用同账号商品列表；单件刷新也直接使用本地所属商品，不重读全店列表。增强列表覆盖最多1000件／50页，超出覆盖或时间预算会明确提示。后台默认预算15分钟，连续3次服务／网络错误停止，遇验证、风险或登录失效立即停止并保留之前的有效缓存，不自动重试或恢复客服。

定期同步默认关闭，可设置6、12或24小时。每周期最多补一批，暂停同步或暂停客服时不调度，首次开启等待一个周期。一次点击可能包含多个平台请求；商品模块只读，不能上架、改价或删除商品。货号从商品描述准确匹配到Excel；存在冲突或缺失时不猜测。商品事实变更会取消尚未发送的旧回复。

## 图片货号核对

成功补取商品详情后，保存有序图片URL并只识别最后一张图。描述货号通过精确规则与知识库匹配，不消耗模型调用；多模态请求不附带描述中的货号，避免诱导图片结果。两者相同采用该货号；不同以描述为准并标记冲突；只有一方提供唯一货号则采用该来源。模糊或多个货号不猜测，未知货号不能凭相似编号匹配材质表。

复用当前统一模型连接；官方DeepSeek端点的图片请求使用文档支持的deepseek-flash，不修改客服文字模型。其他OpenAI-compatible模型需自身支持图片，否则显示核对不可用，仍保留描述资料。仅向模型提交公开可信阿里CDN图片URL，不发送闲鱼Cookie，不新增闲鱼详情接口。相同末图的成功OCR复用；描述变更仍重新计算优先级。图片识别失败不自动重试，管理员可以单件刷新。

每轮图片核对最多20件，额外时间预算5分钟，可随同步暂停／续传。旧缓存缺有序图片字段时需要一次详情补取；可手动分批完成。商品页展示当前所选商品的已缓存图片列表，懒加载可信阿里CDN缩略图，最后一张标记为AI核对图。点击可查看原图；查看商品不会触发闲鱼同步或模型调用。可信CDN的http地址统一转为https。已有图片但缺少核对记录时，下次管理员同步补做识别，无需为此重复补查详情。

客服版商品资料仅保留明确在售／在卖／已发布的商品；已下架、已售出、已删除、草稿及状态不明确的商品不进入资料、详情补查或图片识别。分页以原始商品ID进度判断，避免整页非在售商品导致漏掉后续在售商品。旧本地缓存也按相同规则筛选，无需额外平台请求。

该筛选规则在客服版登录同步、商品同步、快照保存及AI资料读取处统一执行；普通原系统模式保持原有行为。当前账号不在售商品的手工材质绑定、商品补充知识和worker商品详情缓存可归档移除，但聊天记录、登录凭据、模型配置及Excel材质总表不按商品删减。

鞋盒标签识别v2使用原图及两个局部放大视图，在一次模型请求中识别货号/ITEM NO栏，完整保留A、CX等字符，并区分条码附带鞋码。仅当基础货号被知识库精确验证时，程序才去除35至50的末尾鞋码；未知编号不做模糊纠正。旧识别缓存按reader_version失效，下次管理员同步重新核对。商品资料会显示模型给出的简短识别依据。

图片预处理为受限Pillow内存操作：可信CDN HTTPS GET不带Cookie或模型Key，DNS固定验证且禁止重定向，下载≤6MiB/20秒，像素≤2000万，原图和局部视图最长边1600、放大≤2倍，单次请求图文JSON≤8MiB。只在专用图片入口允许JPEG多模态消息，普通文字入口继续拒绝图片内容。不增加闲鱼列表或详情请求。

重新扫码成功后，客服版清除当前账号浏览器中旧商品同步任务锁和旧错误，只重新读取本地资料，不自动发起同步。商品资料返回不透明account_identity区分同一卖家的不同Cookie代次；持久任务必须属于当前代次。失败任务轮询返回明确终态，换登录后的旧任务标记historical/job_superseded，不能用它宣称当前Cookie失效。新同步也不会复用旧Cookie代次的排队任务；网络超时等非终态失败仍保留任务锁，避免重复POST。

## 同步进度与资料变更

账号页与商品页共用当前任务进度，约每2.5秒读取本地任务/进度文件，不增加闲鱼调用。进度按列表、详情、图片核对、保存资料分阶段；已处理包含失败，成功和失败单列；本批待处理与待下批数量分开。列表未读完时总数未知，不把分页上限当总商品数。预计剩余时间使用本阶段实际耗时估计，学习样本不足时显示估算中，暂停/失败停止估计，不伪造倒计时。

增量同步检测列表可靠字段变化；缓存详情超过7天会在下次同步时进入待复查，仍每批最多20件。失败商品不被TTL反复自动重试。只修改正文时，平台列表不一定体现更新，无法不请求详情就保证实时发现。建议修改后点“刷新这件商品”；“重新检查全部详情”会开启一次新的分批复查，后续“继续下一批”只续待补，不重复重置已经完成的商品。定期同步依旧默认关闭。


## 连续对话与 DeepSeek 上下文

客服复用账号私有 SQLite 中持久保存的会话历史，知识模式按会话和商品筛选，模型读取最近 24 条有效消息（约 12 轮，仍有单条与总字符上限）。测试模块同样保留最近 24 条，切换账号或商品沿用原有清空逻辑。买家尺码仅从用户自述提取，不从助手回复或“描述只有41码”推断；尺码 FAQ 的数字示例不能覆盖买家自述，也不能承诺合脚。

DeepSeek Chat Completions 是无状态接口，必须每轮传历史；上下文硬盘缓存默认开启，不等同于永久会话记忆。固定提示词和稳定资料前置、当前问题后置，以利用重复前缀；窗口滑动或知识变更会降低命中，不能保证每次命中。参见 [多轮对话](https://api-docs.deepseek.com/guides/multi_round_chat) 与 [上下文缓存](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)。不为记忆增加闲鱼接口查询，也不增加额外的记忆摘要模型请求。

新增购物寒暄、试穿体验未知和商品概览意图。问脚感时诚实说明缺少试穿反馈，不反复询问用户意图；问其他参数时优先补充未说明的材质。生成失败会返回固定枚举 `generation_fallback_reason` 并记录不含对话和凭据的原因日志；议价校验接受“没法再少”等否定表达，连续议价兜底也使用简短文案。


## 买家连续消息合并

知识客服对同一会话、买家、商品的文字消息使用 3 秒静默窗口，连续输入最长等待 12 秒后处理当前已收集内容。基于已收到消息的时间间隔判断，无法读取买家实际打字状态。原始消息逐条持久保存，短时片段按顺序合并后调用模型；单批最多取 20 条、合计 4000 字。生成期间或发送前发现同一买家同一商品有新的有效文字消息，会放弃尚未发送的旧答案，由后续事件合并处理。已发送的消息不能撤回。

原有回复延迟配置仍在静默等待之后生效，因此总响应时间还包含模型耗时和配置的延迟。人工接管、事件去重、媒体及其他商品的处理保持独立，旧系统通用模式不启用此合并。所有排队检查只读本地 SQLite，不增加闲鱼接口调用。重启后从持久事件和历史恢复未答片段；静默计时会重新开始。


## 稳定的回复表达与有界重写

知识模式在事实核对后生成自然答复，最近 8 条客服答复作为避免重复的参考。对最近 6 条做完整文本检查：忽略标点后的完全相同答复，或长度至少 12 字且相似度达到 0.86 的答复，会触发一次重写；短事实句的共同词不作为相似错误。对价格对话还检查最近 4 条中是否复用了至少 6 字的连续片段，避免换开头却反复追加同一价格结尾；兜底优先选择未复用该片段的表达。重复检查只调整表达，不允许改变材质或政策。

意图识别维持较低随机性，措辞生成使用 temperature 0.65。事实缺失／冲突仍不猜测；已说明的材质不在“还有其他材质吗”时再次全部罗列。尺码已知时不反复索要另一种鞋码；拒绝议价不主动追加购买引导，也不教训反复询价的买家。

一次通常为 1 次意图调用＋1 次措辞调用。重复、未保留事实或不合适的表达至多增加 1 次措辞重写；网络错误不在这一层重复请求。调用失败仍复核知识版本。对明确不议价的已审核政策，兜底只使用可靠的拒绝议价表达，并根据近期答复选取不同措辞，不生成优惠、成本或交易承诺。有限兜底集合不代表无限轮次保证永不重复；长对话、事实型答案仍可能共享词语。原有 worker 瞬时故障重试策略另行生效。

`npm run test:knowledge` 已包含 `tests/reply-style-contract.py`，覆盖重复重写、持续失败下的不同兜底、政策不反转、拒绝重复催单、保持礼貌和知识版本变化保护。真实模型回放仅调用本地试答接口，不发送闲鱼消息，不同步商品。


## 账号页的续期状态

“账号连接”展示最近成功续期、下次计划续期／异常重试、当前续期或认证失败原因。成功时间仅在已有 get_token 调用返回有效令牌后写入本地 auth_status.json；后续失败不会覆盖这个成功时间，旧文件缺字段时显示暂无记录。暂停客服、需扫码或需处理验证时不显示自动执行计划，已过期的计划时间显示等待现有调度执行。

账号页可见时复用现有 5 秒本地轮询，仅读取 GET /api/bot/status；隐藏页面、离开对应页面或退出登录时停止安排轮询，切换账号后忽略旧回执。无新增闲鱼请求、续期任务、登录探测或商品同步。提醒限账号页：登录失效时提示扫码；风控／安全验证时提示先在闲鱼 App 处理；普通网络退避不提示扫码。未增加操作系统推送或后台外部消息。

## 固定 FAQ 原文回复

管理员可在常见问答勾选“按原文回复”，并审核启用。模型仍结合历史识别意图，命中后直接使用审核过的原文，不进行措辞生成或重复改写；本地预览同样生效。未勾选时保留原有自然表达。常见物流问题分别配置时效和承运商 FAQ；不把通常发货政策当成实际订单已发货或已签收的证明。真实政策仅保存在本地知识库，不写进公开源码或样例。

已有 Windows 部署先更新代码，再通过页面保存或 `scripts/update-local-faqs.py --file <本地更新文件>` 合并 FAQ。工具只访问回环地址，使用已有管理员凭据并备份旧 FAQ，按 ID 更新，保留其他问答；运行时不要同时编辑 FAQ。固定回复为新的 FAQ 数据字段，数据兼容版本升为 2；启用后不要直接回退到不能读取该字段的旧版本。

物流问法排查可运行 `python3 scripts/update-local-faqs.py --check --question "下单发什么快递"`，读取本地 FAQ 状态、规则试答原因码和待店主处理的会话数量，不修改 FAQ、不发送消息。附加 `--file <本地更新文件>` 可核对是否漏导入，附加 `--model` 才会调用模型做本地试答。真实聊天曾进入接管后须由管理员明确恢复 AI，修复 FAQ 不会自动解除会话保护。

多账号环境下，更新和检查命令传 `--account <实际account_key>`，与工作台当前选择的账号一致；不传时只检查或更新 default 账号，不会跨账号复制政策。

## 客服专用模式的手动同步

账号连接页只负责扫码授权、授权状态与显示名称；客服启停集中在客服工作台。商品资料页提供手动同步、单件更新及按任务状态显示的暂停与继续；全量详情复查位于“更多操作”。进入页面和查看进度只读本地数据。

客服专用模式不再运行商品定期同步，历史启用配置也不会提交定时任务，接口拒绝重新启用。后台原有调度能力保留供其他模式使用。账号正常续期不受此项调整影响。

最近授权时间只在新授权校验并保存成功后记录；旧版本没有该记录时显示暂无记录。授权时间、资料更新时间、令牌续期时间分别展示。扫码成功仍需在客服工作台手动启动。

## 可选规格与选码建议

“有没有其他尺码／颜色”由当前账号已审核的规格 FAQ 处理，与“这个码是否合脚”的选码建议分开。没有适用资料时仍保留接管保护；不能假定其他链接有货、承诺指定规格补货，或办理订单换码。买家先说平时尺码再询问可选规格时，不用选码追问覆盖已审核的规格答复。

店铺具体规格范围、上新安排与答复放在私有 FAQ 文件中。更新私有源后沿用部署同步入口按 ID 合并，保留其他问答；公开 Git 拉取本身不包含店铺政策。

询问当前链接的码数或确认某码时，使用 `listing_size` 意图读取本地标题／描述中明确的尺码。不会在对话中触发商品同步；选码示例、否定库存、范围或多个冲突尺码不能当作唯一规格，缺少明确资料时说明需以商品页面为准，不用买家自述码数填补。用户表示当前码数不合适时，可匹配审核的可选规格 FAQ。固定 FAQ 按审核原文回答；具体政策仍不进入源码。

选码回复始终以已审核 FAQ 为依据，不再用固定的鞋类型追问或“不保证合适”模板覆盖整条指南。买家自述尺码、FAQ 数字示例与本地商品实际码数分别传给模型；补充鞋类型及催问是否能穿时继续理解选码上下文，不因缺少合脚保证就直接接管。当前尺码答复直接说明“这款是…码哦”。
